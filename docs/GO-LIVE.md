# نقل التحديثات لبياناتك الحقيقية (Go-live)

> الهدف: تحديث النظام (تعدد الوكالات + الصلاحيات + السجل + اللغات + الإيميل + Webhooks) على قاعدة بيانات الإنتاج **بدون فقد أي بيانات**، مع طريق رجوع مضمون.
> الوقت المتوقع: 20–30 دقيقة. الأفضل تعملها وقت هادي (لا أحد بيسجّل فواتير).

## ما اللي هيتغيّر في بياناتك
- كل بياناتك الحالية بتبقى **الوكالة رقم 1**. مفيش حاجة بتتمسح، والـ migration إضافي (أعمدة وجداول جديدة).
- المدير الحالي بيبقى «مدير الوكالة» **ومالك المنصة** (حساب `PLATFORM_ADMIN_EMAIL`، وإلا `ADMIN_EMAIL`).
- أي عضو غير مدير بياخد دور **«عضو»**: يشوف كل شيء تشغيلي **ما عدا** المصاريف الشخصية للـ CEO والفريق والإعدادات والسجل. غيّر أدوارهم بعد التشغيل (محاسب / مدير حسابات / عرض فقط).
- ⚠️ **الكود القديم مش بيشتغل على القاعدة بعد الـ migration** (أعمدة `agency_id` بقت إجبارية). يعني الرجوع = استعادة النسخة الاحتياطية + الكود القديم، مش الكود القديم لوحده.
- ⛔ **ما تستخدمش `docker compose down -v` أبدًا** — ده بيمسح الـ volume اللي فيه قاعدة البيانات.

> ✅ **اتجرّب فعلًا على نسخة من بياناتك الحقيقية** (ملف `TAT-Agency-Full-Migration-Backup`): 39 عميل و39 فاتورة و86 مصروف و59 ميزانية إعلان — كل المجاميع المالية اتطابقت بالجنيه، وتدقيق الأرقام (292 فحص) نجح على النسخة المحدّثة.
>
> **اللي هتلاحظه بعد التحديث (طبيعي):**
> - **سجلات تحصيل جديدة:** كل فاتورة غير مدفوعة بتتربط تلقائيًا بسجل تحصيل (في تجربتك: 12 سجل جديد). مجموع «المتوقع تحصيله» بيزيد بقيمة المتبقي على الفواتير (13,200 + 157,100 = 170,300). ده مقصود، ومش فقدان ولا تغيير في أرقامك.
> - **حساب المدير:** خلّي `ADMIN_EMAIL` في `.env` = إيميل مديرك الحالي بالظبط (مثل `admin@tatagency.com`)، وإلا هيتعمل مستخدم جديد بإيميل مختلف ويبقى هو مالك المنصة. لو عايز مالك منصة مختلف استخدم `PLATFORM_ADMIN_EMAIL`.

## 0) قبل ما تبدأ
- [ ] انسخ الكود الجديد جنب القديم (احتفظ بنسخة من المجلد القديم للرجوع).
- [ ] حدّث `.env` من `.env.example` (المتغيرات الجديدة كلها اختيارية، لكن راجعها):
  - `APP_URL` = عنوان النظام العام (مثل `https://app.example.com`) — لروابط الإيميل.
  - `SECRETS_KEY` = نص عشوائي طويل (`openssl rand -base64 48`) — لتشفير كلمات مرور SMTP. **اكتبه بعد ما تبدأ وماتغيّروش** (لو اتغيّر لازم تعيد كتابة كلمات SMTP).
  - `PLATFORM_ADMIN_EMAIL` لو عايز مالك المنصة غير `ADMIN_EMAIL`.
  - **ماتغيّرش `JWT_SECRET`** (تغييره بيطلّع كل المستخدمين من حساباتهم).
- [ ] تأكد إن عندك مساحة فاضية على القرص تساوي حجم القاعدة على الأقل مرتين.

## 1) النسخة الاحتياطية (إلزامي)
من مجلد المشروع **القديم** والنظام شغّال:
```bash
set -a; . ./.env; set +a
mkdir -p backups
docker compose exec -T db pg_dump -U "$DB_USER" -d "$DB_NAME" -Fc > "backups/before-multiagency-$(date +%F).dump"
ls -lh backups/        # لازم الحجم يكون منطقي (مش صفر)
```
اتأكد إن النسخة سليمة (بتتقرأ):
```bash
docker run --rm -v "$PWD/backups:/b" postgres:16-alpine pg_restore --list "/b/before-multiagency-$(date +%F).dump" | head -20
```
**انسخ ملف الـ `.dump` لمكان تاني** (جهازك / تخزين سحابي) — مش على نفس السيرفر بس.

(اختياري، شبكة أمان إضافية بدون أدوات: `cd backend && npm install && DB_HOST=127.0.0.1 DB_USER=… DB_PASSWORD=… DB_NAME=… node scripts/backup-json.js ./backups/backup.json` — منفذ القاعدة مفتوح على `127.0.0.1` بس.)

## 2) لقطة «قبل» (بصمة البيانات)
على الكود/السكيما **القديمة** (قبل أي تحديث):
```bash
cd backend && npm install
DB_HOST=127.0.0.1 DB_PORT=$DB_PORT DB_USER=$DB_USER DB_PASSWORD=$DB_PASSWORD DB_NAME=$DB_NAME \
  node scripts/migration-snapshot.js save ../backups/snapshot-before.json
```
بيطبع عدد الصفوف في كل جدول ومجاميع الفواتير والمصاريف والإعلانات والتحصيل. **سجّل الأرقام** (أو صوّرها).

## 3) التحديث
```bash
docker compose stop frontend backend          # إيقاف الكتابة (القاعدة تفضل شغّالة)
# ضع الكود الجديد في المجلد، ثم:
docker compose up -d --build
docker compose logs -f backend                # راقب
```
المتوقع في اللوج بالترتيب: `Schema applied successfully.` ← `Marked <admin email> as platform admin.` ← `TAT Agency backend listening on port 4000`.
الـ migration بيتنفّذ كوحدة واحدة: لو فشل أي جزء **بيتلغي كله والقاعدة تفضل زي ما كانت** (والـ backend مش هيقوم). في الحالة دي: ما تعملش حاجة تانية، ابعتلي نص اللوج.

## 4) التحقق «بعد»
```bash
docker compose exec backend node scripts/migration-snapshot.js compare /app/snapshot-before.json
```
(انسخ الملف الأول: `docker compose cp backups/snapshot-before.json backend:/app/snapshot-before.json`، أو شغّل الأمر من الجهاز كما في الخطوة 2 مع `compare ../backups/snapshot-before.json`.)

لازم يطبع `All good — data is intact.` (كل الصفوف والمجاميع زي ما هي، ولا صف بدون وكالة، وكل مستخدم له دور). أي `FAIL` = **لا تفتح النظام للفريق** → خطوة الرجوع.

ثم افحص من المتصفح (10 دقايق):
- [ ] تسجيل الدخول بحساب المدير؛ لوحة القيادة وأرقامها زي ما كانت (قارن بالأرقام اللي سجّلتها).
- [ ] صفحة الفواتير/التحصيل/المصاريف: نفس العدد والإجمالي، وPDF فاتورة بيتولّد.
- [ ] «الفريق والصلاحيات»: كل أعضاء الفريق ظاهرين بأدوارهم.
- [ ] سجّل دخول بعضو عادي: **ما بيشوفش** المصاريف الشخصية ولا الفريق ولا السجل.
- [ ] «سجل النشاط» بيظهر عمليات الدخول والتعديلات الجديدة.
- [ ] تبديل اللغة (EN/ع) من الشريط الجانبي.

## 5) الضبط بعد التشغيل
1. **أدوار الفريق:** من «الفريق والصلاحيات» عيّن لكل عضو دوره (محاسب، مدير حسابات، عرض فقط…) أو أنشئ دورًا مخصصًا.
2. **الإيميل:** «إدارة المنصة ← البريد (SMTP المنصة)» (أو متغيرات `SMTP_*`) ثم «إرسال رسالة اختبار». بعدها جرّب «نسيت كلمة المرور» بحساب تجريبي.
3. **لغة الوكالة الافتراضية:** من «إدارة المنصة ← الوكالات ← تعديل».
4. **Webhooks (لو محتاج):** «الإعدادات ← Webhooks» ← أنشئ واحد واضغط «اختبار».
5. **أول 7 صباحًا بعد التشغيل:** الفحص اليومي بيعلّم الفواتير المتأخرة القديمة **بدون إرسال** (عشان ما يجيش فيضان رسائل)، ويبعت بس للي اتأخر من آخر 3 أيام.
6. **ماتشغّلش** `npm run isolation` ولا `npm run phase3` على الإنتاج (بيعملوا وكالات تجريبية). `npm run audit` مأمون (قراءة فقط).

## 6) لو حصلت مشكلة — الرجوع
```bash
docker compose stop frontend backend
set -a; . ./.env; set +a
docker compose exec -T db psql -U "$DB_USER" -d postgres -c "DROP DATABASE \"$DB_NAME\" WITH (FORCE);"
docker compose exec -T db psql -U "$DB_USER" -d postgres -c "CREATE DATABASE \"$DB_NAME\" OWNER \"$DB_USER\";"
docker compose exec -T db pg_restore -U "$DB_USER" -d "$DB_NAME" --no-owner < backups/before-multiagency-YYYY-MM-DD.dump
# رجّع مجلد الكود القديم ثم:
docker compose up -d --build
```
بعدها قارن بلقطة «قبل» (بـ `save` جديد) للتأكد إن الأرقام رجعت زي ما كانت.

## ملخص الأوامر المهمة
| الغرض | الأمر |
|---|---|
| نسخة احتياطية | `docker compose exec -T db pg_dump -U $DB_USER -d $DB_NAME -Fc > backups/x.dump` |
| بصمة قبل/بعد | `node scripts/migration-snapshot.js save|compare <file>` |
| تدقيق الأرقام (آمن) | `API_URL=… AUDIT_EMAIL=… AUDIT_PASSWORD=… npm run audit` |
| اختبارات الكود | `npm test` |
