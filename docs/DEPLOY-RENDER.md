# الـ backend على Render (مجاني) + Neon (قاعدة مجانية)

## ⚠️ لازم تعرف قبل ما تبدأ
الخدمة المجانية على Render **بتنام بعد 15 دقيقة** من غير طلبات (والصحيان حوالي دقيقة). وهي نايمة: الجدولة (الأحداث اليومية 7 ص، الفواتير الشهرية) وإعادة محاولة الإيميل/الـ Webhooks **ما بتشتغلش**. الذاكرة 512 ميجا فتوليد PDF ممكن يفشل أحيانًا. مناسب للتجربة وللاستخدام الخفيف؛ لشغل فعلي اترقّى لخطة مدفوعة صغيرة أو سيرفر Oracle Free.

## 1) قاعدة البيانات على Neon
1. اعمل حساب على neon.tech ← Project جديد (Postgres 16، منطقة قريبة: Frankfurt).
2. انسخ **Connection string** (بتبدأ بـ `postgres://` وفيها `sslmode=require`).
3. انقل بياناتك (بعد ما تحدّثها محليًا بـ `docs/GO-LIVE.md`):
   ```bash
   pg_restore --no-owner --no-privileges -d "<NEON_URL>" hosted.dump
   ```
   (ملف `hosted.dump` يتعمل بالأمر في `docs/DEPLOY-VERCEL.md` خطوة 3.)
   لو معندكش `pg_restore` على جهازك، قولي وأجهّز لك سكريبت يحمّل الداتا بدونه.

## 2) الـ backend على Render
1. ارفع المشروع على GitHub (Private).
2. Render ← **New → Blueprint** ← اختار الريبو؛ هيقرأ `render.yaml` تلقائيًا.
3. املا المتغيرات اللي بتتسأل عنها:
   - `DATABASE_URL` = رابط Neon.
   - `JWT_SECRET` = **نفس القيمة الحالية** (ماتغيّرهاش).
   - `SECRETS_KEY` = نص عشوائي طويل. `ADMIN_EMAIL` = إيميل مديرك الحالي بالظبط، و`ADMIN_PASSWORD` أي قيمة (مش هتُستخدم لو المدير موجود).
   - `CORS_ORIGIN` و`APP_URL` = عنوان موقع Vercel (اكتبهم بعد ما تنشر الواجهة وتعرف العنوان، وبعدين أعد النشر).
4. بعد النشر: افتح `https://<اسم-الخدمة>.onrender.com/api/health` لازم يرد `{"status":"ok"}` (أول مرة ممكن ياخد دقيقة).
5. الـ migration بيتطبق تلقائيًا مع كل تشغيل.

## 3) منع النوم (اختياري لكنه مهم)
اعمل مراقب مجاني (UptimeRobot أو cron-job.org) يفتح `https://<رابط-الـbackend>/api/health` **كل 5–10 دقايق**. ده بيخلّي الخدمة صاحية. راجع حد الساعات المجانية الحالي عند Render (حوالي 750 ساعة/شهر = خدمة واحدة طول الشهر).

## 4) Vercel
`VITE_API_URL = https://<اسم-الخدمة>.onrender.com` (من غير `/` ومن غير `/api`)، وRoot Directory = `frontend`.
